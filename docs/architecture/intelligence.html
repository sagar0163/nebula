01 · Thinking Engine
The ReAct + Reflexion Loop

Nebula's core cognition is a ReAct loop (Reason → Act → Observe) augmented with Reflexion — learning from mistakes by persisting self-critique into long-term memory.

Planner / Executor Split

Inspired by OpenDev's 2026 architecture: the Planner can only read and search — it cannot execute. The Executor only runs pre-approved steps. This prevents runaway chains where an LLM both decides and acts without a checkpoint.

01
Observe
PTY sentinel detects failure, captures exit code + stderr slice
02
Reason
Fast LLM diagnoses root cause from error + transcript context
03
Search
Cosine search over past fix embeddings, weight by success rate
04
Plan
Stronger LLM proposes ranked fix options (Planner — read-only)
05
Approve
User confirms. No auto-exec without explicit yes (or saved rule)
06
Execute
Executor runs fix inside sandboxed PTY with timeout
07
Reflect
Outcome persisted. Embedding saved. Pattern updated for next time

Doom-Loop Prevention

The agent fingerprints each (command, error-hash) pair. If the same fix is suggested 3× without success, Nebula stops auto-retrying and escalates to the user — preventing infinite healing loops on genuinely broken environments.

02 · Memory Architecture
Four-Layer Persistent Memory

Like a human expert, Nebula has distinct memory systems — each optimised for different retrieval patterns and decay rates.

Working Memory
Current session PTY ring buffer (32KB). Last N commands + outputs. In-memory only — zero latency for context injection.
RAM · transient
Episodic Memory
SQLite: every command, exit code, session, timestamp, workdir. Time-indexed. "What did I do last Tuesday in this repo?"
SQLite · durable
Semantic Memory
Vector embeddings of past failures + fixes. Cosine similarity search. "Find the last time I hit a port conflict and what fixed it."
float32 vectors · SQLite
Procedural Memory
Learned workflow patterns — frequent command sequences (freq-itemset mining). "After git commit you usually run git push origin HEAD."
patterns · proactive

Context Window Management

Long sessions hit LLM context limits. Nebula uses a 5-stage progressive compaction from OpenDev's research: raw transcript → filtered → summarised → key-facts → single-sentence. Each stage halves the token count while preserving the causal chain needed for healing decisions.

// Five-stage context compaction Stage 1: Raw ring buffer // 32KB — last 200 lines Stage 2: Filter noise // 16KB — strip progress bars, spinners Stage 3: Summarise per-command // 4KB — cmd + exit + 1 sentence outcome Stage 4: Key facts only // 1KB — errors, fixes, env facts Stage 5: Single causal sentence // 200t — "port conflict, remapped to 5433"

Streaming Architecture

Every completion streams — tokens arrive as tea.Msg events in the bubbletea TUI, keeping the UI responsive. Three channels surface to the UI: content deltas, tool-call deltas (rendered as "running git status…"), and final usage/cost. Context is always cancellable — Ctrl+C kills the stream and the PTY child cleanly.

Proactive Trigger System

⊕

Workflow Momentum

Freq-itemset mining over command history detects N-grams ("commit → push → PR"). After the first step, Nebula suggests the next.

⊛

Context Change Detector

Watches for: directory change, git branch switch, new .env.example, Docker file changes. Each triggers a relevant check or suggestion.

⊜

Pre-emptive Failure Scan

Before you run a known-risky command, Nebula checks if its preconditions are met (port free? service running? credentials set?).

⊝

Universal Predictor

Semantic similarity search over past sessions: "this looks like that time you were deploying to staging — here's what tripped you up."

⊞

Ambient Health Monitor

Watches background services (Docker, k8s, DB) and surfaces alerts when something relevant to your current task starts failing.

⊟

Session Continuity

On startup, scans last session for incomplete workflows. "You were deploying yesterday — the migration never ran. Continue?"

Butler Personality Principles

A good butler surfaces information at the right moment, never intrudes, and learns when to stay quiet. Nebula enforces three rules:

One suggestion at a time
Never queue multiple suggestions. Surface the most relevant, suppress the rest.
Learn silence
User says "n" three times to the same pattern → permanently suppress it. [s] key saves a "stop suggesting this" rule.
Zero blocking
Butler suggestions never block the prompt. They appear as a non-blocking overlay and auto-dismiss after 10s.
05 · Safety Architecture
Five Independent Defense Layers

Each layer can stop a class of harm independently. Safety is not a checkbox — it's a pipeline that runs before any AI-suggested command touches the OS.

// safety pipeline — every AI-suggested command passes all five
flowchart TD
  A[AI Suggests Command] --> B[Layer 1\nParse + Classify\nsafe / low / medium / high / dangerous]
  B -- dangerous --> DENY[🚫 Hard Deny\nno override]
  B -- safe/low --> C[Layer 2\nPermission Engine\npersisted allow/ask/deny rules]
  B -- medium/high --> C
  C -- deny --> DENY2[🚫 Policy Deny]
  C -- ask --> D[Layer 3\nUser Approval\ny/n/edit/explain/save-rule]
  C -- allow --> E[Layer 4\nOS Sandbox\nbubblewrap Linux\nsandbox-exec macOS]
  D -- yes --> E
  D -- no --> REJECT[↩ Rejected]
  E --> F[Layer 5\nRuntime Controls\ntimeout · doom-loop · audit log]
  F --> G[✓ Execute]
  G --> H[(Audit Log\nappend-only SQLite)]
⬡

Hard-Deny Vectors

Interpreter bypass vectors are always denied regardless of rules: bash -c, python -c, node -e, sudo — these let an LLM execute arbitrary code by wrapping the real command.

⬡

Context Scrubber

Before any text is sent to an external LLM: regex strips AWS_*, sk-*, GITHUB_TOKEN, and similar patterns. Your secrets never leave the machine.

⬡

Git Snapshot Undo

Before any file-mutating command, Nebula offers to snapshot via git stash. One keystroke rolls back any AI-applied edit.

06 · Research & Prior Art
Ideas Worth Adopting

Synthesis of academic papers, production systems, and industry patterns that directly inform Nebula's architecture. Rated by adoption priority.

Academic Foundations

CORE 2022

ReAct: Synergizing Reasoning and Acting

Yao et al. (Google). Interleaving chain-of-thought reasoning with tool actions. The LLM thinks aloud before acting — dramatically improves success rate on multi-step tasks vs. pure acting.

✓ Adopt — foundation of Nebula's diagnose loop
CORE 2023

Reflexion: Language Agents with Verbal Reinforcement

Shinn et al. Agents write self-critiques after failure and store them in memory. Next attempt starts with the critique as context. Raises task success from 73% → 91% on benchmarks.

✓ Adopt — powers Nebula's pattern learning + improve loop
CONSIDER 2023

Tree of Thoughts

Yao et al. Instead of one fix suggestion, explore a tree of candidates, evaluate each, prune bad branches. Best for ambiguous failures where the cause isn't obvious.

→ Consider for multi-step healing chains (v2)
CORE 2026

OpenDev: Agentic Shell Architecture

Planner/Executor split, workload-specialized routing, 5-stage context compaction, lazy MCP tool discovery, two-phase memory, doom-loop detection. First published paper to systematize production CLI agent design.

✓ Adopt — multiple patterns directly in Nebula
WATCH 2024

MemGPT: LLMs as Operating Systems

Treats context window as main memory, SQLite as disk. Self-directed memory paging — the LLM decides what to recall and evict. Enables effectively unbounded context.

◎ Watch — implement simplified version for long sessions
CONSIDER 2024

AAIF Agent-to-Agent Protocol

Linux Foundation standard for multi-agent communication. Nebula could spawn specialist sub-agents (docker-expert, k8s-expert) and coordinate via A2A for complex failures outside its own training.

→ Consider for multi-agent healing (v2)

Production Systems

ADOPT Codex CLI

Exec Policy Rule Engine

DSL-based allow/deny rules in ~/.codex/rules/. Pattern: Bash(git push:*) allows all git push variants. Subcommand-aware so you can't bypass with git --exec-path.

✓ Adopt — implement DSL for Nebula's permission rules
ADOPT Warp Terminal

Block-based Command Output

Each command is a discrete block with its own exit status, timing, and AI annotation. Output is never a stream of raw bytes — it's structured, scrollable, and searchable.

✓ Adopt — Nebula TUI should treat each command as a typed block
ADOPT Claude Code

Background Task Promotion

Long-running commands are "promoted" to a background task with a spinner. The REPL stays responsive. On finish, a notification appears with the result — no blocking.

✓ Adopt — critical for slow builds/deploys in Nebula
CONSIDER Goose / AAIF

JSON-RPC App Server

Decouple the agent runtime from the TUI by exposing it over stdio JSON-RPC. The same core can power the terminal TUI, a VS Code extension, a web UI, or another agent as a tool.

→ Consider for v2 — enables IDE integration without rewrite

Proposed New Ideas for Nebula

◈

Confidence-Gated Auto-Healing

Only auto-apply fixes when semantic memory confidence ≥ 0.95 AND the same fix has worked 3+ times. Anything below that threshold always asks. Confidence shown to user inline.

◈

Failure Taxonomy

Classify every failure into a structured type: NetworkError / PortConflict / PermissionDenied / MissingDep / ConfigMissing. Route each type to a specialized sub-prompt tuned for that class.

◈

Community Pattern Sync

Anonymized, opt-in: export your success patterns (cmd-hash + fix-hash + success-rate, no content) to a community DB. Pull community fixes for errors you've never seen before.

◈

Offline-First with Sync

Full functionality with local Ollama (nomic-embed + llama3.2). When online, stronger models augment but never replace local memory. Your data stays on-machine permanently.

◈

Evals as First-Class Feature

Every healing attempt logged as: (failure, suggestion, applied, outcome). Built-in nebula eval command shows your personal heal-rate dashboard — self-healing is measurable, not marketing.

◈

Shell-Native Init Hook

eval "$(nebula init bash)" injects PROMPT_COMMAND sentinels and keybindings at shell level — no PTY wrapping needed. Deeper integration, lower overhead, works in any terminal.
